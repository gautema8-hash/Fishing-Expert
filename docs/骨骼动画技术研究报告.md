# 骨骼动画系统技术研究报告

## 一、问题背景

虾堡捕鱼达人游戏原使用 Canvas2D + 静态图片渲染鱼类。Fish.js 中虽已实现程序化骨骼动画（脊椎S形摆动、Verlet鱼鳍物理、7种动画状态），但 `render()` 方法在图片加载完成后优先走 `_renderImage()` 路径——该路径仅执行 `drawImage` 整张图片 + 微小 sin 摆动，**完全绕过了骨骼动画系统**。导致用户看到的鱼儿只是一张图片整体平移旋转，没有身体分段弯曲、鱼鳍扇动、乌龟划水等真实运动。

## 二、GitHub成熟方案调研

### 2.1 商用捕鱼游戏的动画实现方式

通过研究 GitHub 上成熟的 HTML5 捕鱼游戏项目（如 fishing-game、fish-hunter、golden-fish 等）以及商业捕鱼游戏（如《捕鱼达人》《海王捕鱼》）的技术分享，主流实现方式分为三类：

| 方案 | 代表项目/工具 | 优点 | 缺点 |
|------|-------------|------|------|
| **Spine/DragonBones 骨骼动画** | Esoteric Spine、DragonBones、Phaser Spine Plugin | 专业级骨骼绑定、Mesh变形、可在编辑器中调动画 | 需要美术导出骨骼数据、运行时库体积大、Canvas2D支持有限 |
| **精灵序列帧动画** | 传统2D游戏、TexturePacker | 实现简单、效果可控 | 资源体积大（每条鱼需数十帧）、内存占用高 |
| **程序化骨骼+图片切片** | 各类轻量HTML5游戏、procedural animation 教程 | 无需额外美术资源、运行时计算、文件体积小 | 需要程序实现骨骼系统、效果依赖算法质量 |

### 2.2 关键技术发现

**Spine 的 2D Mesh 变形原理**：Spine 将图片绑定到网格（Mesh），网格顶点受骨骼权重影响，骨骼运动时顶点位置通过双线性插值计算，实现图片的平滑变形。这是商用游戏真实感的核心。

**程序化解剖动画（Procedural Animation）**：通过正弦波驱动脊椎链（Vertebral Column），头部摆幅小、尾部摆幅大，形成自然的 S 形波动。这是鱼类游动的生物力学基础。

**四肢交替运动（Gait Pattern）**：四足动物的对角线步态（前左+后右 → 前右+后左）是乌龟/海龟划水的自然模式。

**触手波动（Tentacle Wave）**：章鱼触手通过多段骨骼的相位偏移正弦波实现从根部到尖端的波动传播。

### 2.3 技术选型决策

考虑到项目现状（Canvas2D、已有完整鱼类图片、已有程序化骨骼动画代码），选择 **轻量级程序化骨骼 + 图片切片变形** 方案：

1. **不引入 Spine/DragonBones**：需要美术重新导出骨骼数据，工作量大，且 Canvas2D 运行时支持不完善
2. **不使用序列帧**：60+ 种鱼类 × 数十帧 = 巨大资源体积，不可接受
3. **图片切片+骨骼驱动**：将已有整鱼图片沿身体轴向切成 N 个垂直条带，每条带绑定一节脊椎骨骼，渲染时按骨骼位置/角度独立绘制，条带间重叠掩盖接缝。这本质上是 Spine Mesh 变形的轻量实现，无需额外美术资源

## 三、系统架构

```
frontend/js/animation/
├── Bone.js                  # 骨骼基类（父子层级、世界坐标预计算）
├── Skeleton.js              # 骨架基类（骨骼管理、动画状态、迭代更新）
├── FishSkeleton.js          # 鱼类骨骼（脊椎S波+胸鳍+动态节数）
├── ImageSlicer.js           # 图片切片工具（垂直条带+缓存）
├── SkeletalFishRenderer.js  # 鱼类骨骼渲染器（切片变形+鳍叠加）
├── TurtleRenderer.js        # 乌龟渲染器（四腿交替划水+头伸缩）
├── OctopusRenderer.js       # 章鱼渲染器（外套膜呼吸+8触手波动）
└── JellyfishRenderer.js     # 水母渲染器（伞盖收缩+触手飘动）
```

### 3.1 核心算法：图片切片骨骼变形

```
整鱼图片（头朝右）
    ↓ 垂直切为 N 条带（slice[0]=尾, slice[N-1]=头）
    ↓ 每条带左右扩展 overlapPx 用于重叠
脊椎骨骼链（头→尾，头摆幅0.3x，尾摆幅1.5x）
    ↓ 每节局部角度 = sin(time*freq - i*phase) * amp * ampRamp
    ↓ 世界角度 = 父骨骼世界角度 + 局部角度（前向运动学）
渲染：从尾→头遍历，每条带 translate 到骨骼世界坐标 → rotate 到骨骼角度 → drawImage
```

### 3.2 生物类型路由

Fish.js 通过 `_detectCreatureType()` 识别生物类型，路由到对应渲染器：

| 类型 | 识别规则 | 渲染方式 |
|------|---------|---------|
| fish | 默认（金鱼、小丑鱼、鲨鱼等50+种） | FishSkeleton + 图片切片变形 |
| dragon | goldendragon/blackdragon | FishSkeleton（更多节数） |
| turtle | turtle | TurtleRenderer（四腿划水） |
| octopus | octopus/squid/cuttlefish等 | OctopusRenderer（触手波动） |
| jellyfish | jellyfish/splitfish | JellyfishRenderer（伞盖收缩） |
| crustacean | crab/lobster/giant_isopod | 静态图片（肢体结构特殊） |
| echinoderm | starfish/sea_urchin等 | 静态图片 |

## 四、性能优化

| 优化项 | 实现方式 | 效果 |
|--------|---------|------|
| **动态切片数** | FishSkeleton.optimalSegments()：小鱼6节、中鱼7-8节、大鱼用配置值 | 减少drawImage调用 |
| **远景降级** | depth=far 且 size<80 的鱼回退静态图片 | 远景鱼半透明缩小，骨骼效果不明显 |
| **极小图降级** | size<24 的鱼回退静态图片 | 极小图切片无意义 |
| **骨骼实例复用** | FishSkeleton.configure() 复用对象池中的骨骼，仅更新参数 | 避免GC压力 |
| **世界坐标预计算** | Bone.computeWorld() 直接写入 wx/wy/wAngle 公共字段，无对象分配 | 消除每帧数百个临时对象 |
| **迭代式更新** | Skeleton.update() 按根→叶顺序计算，避免递归 | O(n) 复杂度 |
| **切片缓存** | ImageSlicer 按 imageSrc+sliceCount 缓存切片画布 | 同种鱼只切一次 |
| **骨骼索引缓存** | SkeletalFishRenderer 用 Int8Array 缓存切片→骨骼映射 | 消除每帧 Math.round 计算 |
| **小鱼跳过鳍叠加** | size<35 的鱼不画程序化胸鳍 | 减少渐变创建和路径绘制 |

## 五、动画状态机

继承原有 7 种动画状态，每种状态有独立的频率/幅度倍率：

| 状态 | 触发条件 | 身体频率 | 身体幅度 | 尾部幅度 | 弯曲度 |
|------|---------|---------|---------|---------|--------|
| idle | 速度<50% | 0.5x | 0.6x | 0.5x | 0.7x |
| swim | 正常游动 | 1.0x | 1.0x | 1.0x | 1.0x |
| fast | 速度>130% | 1.5x | 1.2x | 1.5x | 1.5x |
| turn | 转向速率>6rad/s | 1.0x | 1.3x | 1.2x | 1.4x |
| escape | 躲避炮弹 | 2.0x | 1.6x | 1.8x | 1.6x |
| hurt | 受击僵直 | 3.0x | 0.3x | 0.3x | 0.5x |
| dying | 死亡 | 0.3x | 0.2x | 0.2x | 0.5x |

速度影响：`实际频率 = 基础频率 * (1 + (speedRatio - 1) * 0.5)`，游得快摆得快。

## 六、降级策略

三级降级确保游戏不白屏：

1. **骨骼动画**（图片+骨骼）→ 首选，真实身体弯曲
2. **静态图片**（_renderImage）→ 骨骼渲染失败时自动降级，保留原有效果
3. **程序化绘制**（原有 _renderBody 等）→ 图片加载失败时的最终 fallback

## 七、验证结果

- ✅ 鱼儿身体有 S 形摆动动画（头部摆幅小、尾部摆幅大）
- ✅ 鱼的胸鳍独立扇动（中等以上鱼叠加程序化胸鳍）
- ✅ 鱼尾跟随身体摆动（尾部切片随尾骨大角度旋转）
- ✅ 乌龟四条腿交替划水（对角线步态）
- ✅ 乌龟头部可伸缩（周期2秒正弦波）
- ✅ 章鱼触手独立摆动（8条触手相位偏移波动）
- ✅ 水母伞盖收缩舒张（scaleY 脉冲 0.7~1.1）
- ✅ BOSS 龙身波浪扭动（16节脊椎长身波动）
- ✅ 游得快时动画频率加快（speedInfluence）
- ✅ 转弯时身体弯曲（turnBend 叠加）
- ✅ 控制台 0 错误
- ✅ 静态图片渲染作为 fallback 保留
