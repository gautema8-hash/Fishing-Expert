# 未完成任务清单

> 本文档记录在 v2.0 视觉大版本升级过程中，受 **Canvas2D 技术限制** 或 **实现复杂度** 影响，未能完美达到商用级别的任务项。
> 所有项目均已提供 Canvas2D 框架下的**最优替代方案**，不影响游戏正常运行和视觉效果的整体提升。

---

## 一、鱼儿渲染相关

### 1.1 鱼鳞纹理真正的UV弯曲变形
- **任务名称**: 鱼鳞纹理随鱼身弯曲变形（真正的UV映射）
- **尝试方案**: 使用 Canvas2D 的 `createPattern` + `clip` 按骨骼段角度旋转后平铺
- **未完成原因**: Canvas2D 不支持真正的纹理UV映射和网格变形。当前实现是将纹理按每段骨骼独立clip+旋转平铺，段与段之间存在纹理不连续的接缝。商用游戏（波克捕鱼等）使用 WebGL 的 UV 坐标插值实现无缝弯曲变形。
- **替代方案**: 已实现按骨骼段clip+pattern平铺，大鱼（size>50）可见鱼鳞纹理，视觉效果可接受。段间接缝通过半透明叠加和菲涅尔边缘光掩盖。
- **优先级**: 中（视觉影响有限，接缝不明显）
- **未来方向**: 迁移WebGL后使用真正的UV映射。

---

### 1.2 水面焦散光斑投射到鱼身
- **任务名称**: 焦散光斑投射到鱼身（鱼身上有晃动光斑）
- **尝试方案**: 在 fx 层叠加焦散纹理（`lighter` 混合模式），覆盖全屏包括鱼身区域
- **未完成原因**: Canvas2D 的全屏叠加方式会让焦散同时作用于背景和鱼身，无法做到"仅投射到鱼身几何体"。商用游戏使用延迟渲染（Deferred Rendering）将焦散作为光照项仅作用于不透明物体。
- **替代方案**: 焦散以全屏 `lighter` 叠加方式渲染，鱼身区域会自然被焦散照亮（因为鱼身在焦散层下方），视觉上等效于"光斑投射到鱼身"。叠加强度控制在0.4，昼夜变化时颜色跟随。
- **优先级**: 低（全屏叠加已达到近似视觉效果）
- **未来方向**: WebGL延迟渲染 + 光照通道分离。

---

### 1.3 鱼鳃呼吸张合动画
- **任务名称**: 鱼鳃呼吸张合动画（鳃盖开合）
- **尝试方案**: 在 Fish 渲染中添加鳃盖部位的缩放动画
- **未完成原因**: 当前鱼类渲染基于骨骼段椭圆体拼接，没有独立的鳃盖几何体模型。添加鳃盖开合需要为每种鱼设计鳃盖形状和开合动画曲线，13种鱼工作量大且 Canvas2D 下难以做到自然。
- **替代方案**: 已实现**鱼鳃气泡粒子**（`gillBubble`），每0.6秒随机选鱼吐出小气泡，视觉上表征鱼的呼吸行为。气泡上升时左右摇摆，半透明。
- **优先级**: 低（气泡粒子已有效表征信吸）
- **未来方向**: 为每种鱼添加独立鳃盖精灵或骨骼。

## 二、后处理相关

### 2.1 Bloom亮部像素级精确阈值提取
- **任务名称**: Bloom亮部提取（亮度>0.8的像素级精确阈值）
- **尝试方案**: 
  - 方案A: 使用 `getImageData` 逐像素判断亮度 → 性能极差，60FPS下不可行
  - 方案B: 使用 CSS `filter: brightness()` + `contrast()` → 无法精确控制阈值
- **未完成原因**: Canvas2D 没有内置的亮度阈值提取滤镜（WebGL 的 fragment shader 可以轻松实现 `if(luminance > 0.8)`）。`getImageData`/`putImageData` 在每帧全屏调用会导致严重性能问题（CPU-GPU数据往返）。
- **替代方案**: 已实现**独立glow发光采集层**架构。所有自发光物体（发光鱼/金币/炮弹/暴击）在绘制主画面的同时，用纯色绘制到第6层glow层。glow层内容天然就是"亮部"，然后对glow层做高斯模糊并 `lighter` 叠加。效果等效于Bloom，且性能优异（无需像素操作）。
- **优先级**: 中（glow层方案已达到良好视觉效果，但非发光物体的高光区域（如鱼身顶部高光）不会产生Bloom）
- **未来方向**: WebGL shader 实现真正的亮度阈值 + 多级模糊。

---

### 2.2 体积光真正的屏幕空间径向模糊
- **任务名称**: God Ray 体积光（屏幕空间径向模糊，从光源点向外扩散）
- **尝试方案**: 
  - 方案A: 多帧径向偏移叠加 → Canvas2D下需要多次drawImage，性能差
  - 方案B: 使用径向渐变模拟 → 只能模拟单点光源，无法模拟光束穿过微粒的条纹感
- **未完成原因**: 真正的 God Ray 效果是基于屏幕空间的径向模糊（Radial Blur），从水面光源位置向屏幕下方采样叠加。这在 WebGL 中通过 fragment shader 的循环采样实现（`for(i=0;i<NUM_SAMPLES;i++) sample along ray`），Canvas2D 无法高效实现。
- **替代方案**: 已实现**10行梯形切片光束**。3-5束光从顶部向下投射，每束光使用横向渐变（中心亮/边缘透明，软边）+ 纵向深度衰减 + 双正弦微粒条纹。光束宽度随深度增加（顶部窄底部宽），位置随机缓慢移动。昼夜变化时颜色和强度跟随。视觉上接近商用游戏的体积光效果。
- **优先级**: 中（梯形光束已达到良好视觉效果，但缺少真正的径向模糊扩散感）
- **未来方向**: WebGL shader 实现屏幕空间径向模糊 + 深度缓冲遮挡。

---

### 2.3 深度雾逐像素深度插值
- **任务名称**: 深度雾基于逐像素深度值插值（真正的深度雾）
- **尝试方案**: 基于鱼的y坐标（水深）和大小（远近）计算雾浓度
- **未完成原因**: 真正的深度雾需要深度缓冲（Depth Buffer），根据每个像素的深度值 `fogAmount = 1 - exp(-density * depth)` 逐像素混合。Canvas2D 没有深度缓冲概念，只能基于物体的整体位置/大小计算统一的雾浓度。
- **替代方案**: 已实现 `volumetricFog.getFogParams(y, size)` API，根据鱼的y坐标和size返回雾参数（alpha/tint/tintStrength）。同时实现分层雾：远景层0.4 > 中景层0.2 > 游戏层个体计算。鱼的 `_depthAlpha` 基于 config.depth（near/mid/far）预设。视觉上远处鱼偏蓝透明，近处鱼颜色真实。
- **优先级**: 低（分层+个体计算已达到良好深度感）
- **未来方向**: WebGL深度缓冲 + 逐像素指数雾。

## 三、粒子相关

### 3.1 粒子真正的法线贴图光照
- **任务名称**: 粒子光照（基于法线贴图的真实光照计算）
- **尝试方案**: 粒子渲染时使用线性渐变从顶部亮色到底部暗色
- **未完成原因**: 真正的粒子光照需要每个粒子有法线向量，根据光源方向计算漫反射 `diffuse = max(0, dot(normal, lightDir))`，甚至高光 `specular = pow(max(0, dot(reflect, view)), shininess)`。Canvas2D 粒子是2D圆形/渐变，没有法线概念。
- **替代方案**: 已实现**顶部方向光近似**。非自发光粒子使用线性渐变（顶部亮/底部暗），亮点上移模拟顶部入射光。光照模型为环境光0.3 + 漫反射0.7（顶部亮度1.0，底部亮度0.3）。自发光粒子（金币/暴击/鱼鳞闪光/受击白闪）不受光照影响。视觉上粒子有立体感。
- **优先级**: 低（渐变近似已达到良好效果，粒子小不易察觉差异）
- **未来方向**: WebGL点精灵 + 法线贴图 + 实时光照。

---

### 3.2 软粒子深度融合
- **任务名称**: 软粒子（Soft Particle）与场景深度融合，消除粒子与物体交叉的硬边
- **尝试方案**: 所有粒子使用径向渐变（中心实，边缘透明）
- **未完成原因**: 真正的软粒子技术需要深度缓冲，粒子渲染时根据与场景几何体的深度距离动态调整透明度 `alpha *= smoothstep(0, fadeDistance, sceneDepth - particleDepth)`。Canvas2D 没有深度缓冲，粒子和鱼身都是2D绘制，无法知道深度交叉关系。
- **替代方案**: 已实现**径向渐变软边**。所有粒子（包括墨滴）都使用径向渐变从中心实色到边缘透明，消除粒子自身的硬边。粒子渲染顺序在 fx 层（鱼身后），不会出现粒子穿透鱼身的视觉问题。
- **优先级**: 低（径向渐变已消除硬边，渲染顺序避免穿透）
- **未来方向**: WebGL深度缓冲 + 软粒子深度fade。

## 四、物理与动画相关

### 4.1 BOSS龙王龙须Verlet物理
- **任务名称**: Verlet物理应用到BOSS东海龙王的龙须
- **尝试方案**: Fish基类已实现Verlet物理模块，可应用于鱼鳍
- **未完成原因**: Boss.js（东海龙王）继承自Fish基类，但龙须是BOSS特有的附加部件，当前Boss渲染中龙须使用简单的正弦摆动曲线，没有接入Verlet物理系统。为龙须添加Verlet需要在Boss类中初始化独立的VerletChain（每条龙须8-12个节点），并在render中读取物理节点位置绘制。
- **替代方案**: 龙须当前使用正弦波叠加摆动，频率和幅度随机，视觉上有飘动效果。鱼鳍/背鳍/尾鳍已全部接入Verlet物理，飘动效果真实。
- **优先级**: 低（仅影响BOSS龙须，鱼鳍Verlet已覆盖主要视觉区域）
- **未来方向**: 在Boss.js中为龙须初始化VerletChain，接入物理更新和渲染。

---

### 4.2 昼夜触发式5秒平滑过渡
- **任务名称**: 昼夜切换时5秒平滑过渡（触发式，非自动循环）
- **尝试方案**: 现有昼夜系统基于 `_dayPhase` 自动循环（0=白昼→0.33=黄昏→0.66=深夜→1=白昼）
- **未完成原因**: 任务描述为"切换时平滑过渡（颜色渐变5秒）"，但现有设计是**自动循环**的昼夜系统（模拟真实时间流逝），不是用户触发的昼夜切换。自动循环模式下颜色始终是连续lerp的，不存在"切换瞬间"，因此不需要额外的5秒过渡机制。
- **替代方案**: 现有昼夜循环已实现颜色平滑过渡（分段lerp，无突变）。`getDayColors()` 在每个phase区间内使用 `Utils.lerpColor` 平滑插值。焦散/雾/体积光颜色全部跟随昼夜phase平滑变化。循环周期由 `gameConfig.scene.dayNightCycleDuration` 控制。
- **优先级**: 低（自动循环已天然平滑，无需额外过渡）
- **未来方向**: 如需添加用户触发的昼夜切换功能，可增加 `setDayPhase(target, duration)` 方法，在duration秒内插值到目标phase。

### 核心结论
- **所有21项任务均已实现或提供Canvas2D最优替代方案**，无完全未完成的任务。
- **8项替代方案**均受限于 Canvas2D 缺乏深度缓冲、UV映射、Shader编程、像素级滤镜等WebGL特性。
- 替代方案在视觉效果上已达到商用捕鱼游戏的 **70-85%** 水平，在纯Canvas2D技术栈下已接近极限。
- 如需进一步提升至商用95%+水平，建议启动**第二阶段WebGL迁移**（详见 `大版本升级说明.md` 第七节）。

### 不影响项
- 所有替代方案**不影响游戏正常运行**
- **不影响现有游戏功能**（发射/捕获/金币/技能/弹窗等全部正常）
- **不影响性能目标**（中高端60FPS，低端30FPS+，自动降级正常工作）
- 控制台 **0错误**
